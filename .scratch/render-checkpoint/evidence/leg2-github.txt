RED RIDER — WebKit (Safari), downscaled display only:

  (First seen on github.com itself: github-live.mjs drove WebKit, so

  surface. Locally isolated in leg2-webkit-img-758.png vs
  leg2-webkit-img-1440.png; leg2-local-chrome.png is the correct render.)
- Bisected: not the hydration comments, not the @container tiers, not
  display:list-item, not font size (chips render smaller text fine).
- Minimal repro (leg2-minrepro-scaled.png, webkit-min-repro.mjs family):
  a foreignObject containing <li style="position:relative;padding-left">
  paints UNSCALED when the <img> displays below natural size — the text
  draws at full size and escapes the image's box, while sibling <p>/<div>/
  plain <li> scale correctly. `.stack li { position: relative }` is exactly
  the sheet's rule for the four dead sections (CanvasSheet.svelte:975).
- Canvas drawImage() of the same image rasterizes correctly at every size —
  the defect is WebKit's display path only.

Verdict: the committed image is fully correct on GitHub in Chromium-family
readers; in Safari the four .stack sections vanish at README scale. Goes
back to the map (owner: committed-images / committed-images-build): the
plausible fix direction is laying out .stack li without position:relative
(the marker via ::marker or an inline glyph instead of an absolutely
positioned ::before against a relative li), then re-rendering the four
images — but that is the owning ticket's call, not the checkpoint's.
