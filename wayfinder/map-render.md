# Wayfinder map: the canvas leaves the browser

## Destination

A canvas committed in a repo **renders in a markdown file** — on GitHub through a committed `.bcc.svg`, and in VS Code's preview through a `bcc` fence — from **one renderer that runs in Node with no browser**. `bcc render`, `check`, `fmt` and `ls` drive it from a checkout. The MCP surface has been re-sized with [workshop-drive](wayfinder/tickets/034-workshop-drive.md)'s evidence in hand. And the byte-identity property holds: **the sheet the CLI renders and the sheet the editor exports are the same sheet**, proved on all four examples, not asserted.

## Notes

- **This map carries execution**, like the hosting, examples, canonical-v5 and views maps before it. The product is shipped and live; these are increments on it, so task tickets *do* — build, render, rebuild — once the decision and research tickets clear.
- **The finding this map is built on, established before charting (2026-08-13):** `CanvasSheet.svelte` renders through Svelte 5's `svelte/server` `render()` in plain Node — no DOM, no jsdom, no headless Chromium — and the result is pixel-faithful. It works because the sheet uses **zero Tailwind utility classes except `sr-only`**: all 551 lines of its styling are Svelte-scoped CSS reading 26 custom properties, every one declared in the single `@theme` block in `src/app.css`. Measured: 31.8 KB standalone without fonts, 204 KB with 8 WOFF2 faces base64'd from disk, against ~446 KB for the browser export (which inlines the entire compiled stylesheet — Tailwind preflight, every utility, and the scoped CSS of Chrome, EditableSheet, Picker, JsonView — to render a read-only sheet). This retires `mcp/README.md`'s standing claim that writing an artifact *"would mean rendering the sheet, which needs a browser."* Probe scripts in `.scratch/helicopter/`.
- **Settled context (from charting, 2026-08-13):**
  - **Both asks are in scope.** "Renders like mermaid" was two asks wearing one sentence — *renders while I write* (an editor extension point) and *renders in the repo* (a committed image plus a build-time plugin). The map takes both. They share almost no implementation, which is why they are separate tickets rather than one.
  - **GitHub has no fence route, for anyone.** Its supported list — mermaid, GeoJSON, TopoJSON, ASCII STL — has no registration mechanism behind it, and inline `<svg>` in markdown is dropped whole (the sanitizer's allowlist carries `img` and no `svg`, no `foreignObject`, no `style`). The committed image is not a compromise reached after trying; it is the only surface that exists.
  - **The committed image is an SVG, not a PNG** — settled green by [github-svg-probe](wayfinder/tickets/049-github-svg-probe.md). A `foreignObject` SVG wraps *the same HTML the headless renderer already emits*, so it needs no browser at all, where PNG needs real layout and therefore Playwright. It is also ~10× cheaper in the repo: the font payload is byte-identical across canvases, so git's delta compression collapses it (152 KB for four sheets against 1,472 KB of PNG). PNG stays available for anything that is not a web engine.
  - **Claude Desktop is out of scope for now** — a scoping call on current use, explicitly not "Desktop is dead". It was the entire justification for a server over a skill-plus-CLI ([mcp-server-shape](wayfinder/tickets/025-mcp-server-shape.md) decision 3: *"The server wins on reach… If Claude Code were the only target, the skill would be the right answer."*). With it out, the diet ticket is allowed to propose moving writing and listing to the CLI. If Desktop comes back, that ticket's answer is what gets revisited, not this map's destination.
  - **The CLI is repo-local and unpublished**, run from a checkout. This holds [mcp-server-shape](wayfinder/tickets/025-mcp-server-shape.md) decision 1 (`private`, publishing deferred to evidence) rather than quietly overturning it.
  - **`src/lib/model/` does not move.** [mcp-server-shape](wayfinder/tickets/025-mcp-server-shape.md) decision 5 rejected lifting it to a neutral top-level package as *"a rename touching most of the app, SPEC's file map and every test"* — rejected when the model layer had one consumer. This map takes it to four or five, and the answer is unchanged: because every new consumer is repo-local (above), each reaches the model through the same `$lib/*` alias `mcp/tsconfig.json` already uses, and the rename buys nothing until something is published to somebody else.
  - **VS Code, not Obsidian.** Obsidian is the cleanest API fit in the survey — `registerMarkdownCodeBlockProcessor` hands you a div and expects arbitrary DOM, mapping 1:1 onto `src/lib/artifact/offscreen.ts`'s existing `mount(CanvasSheet, …)`. It is also the worst workflow fit: [mcp-server-shape](wayfinder/tickets/025-mcp-server-shape.md) decision 2 fixed the model as canvases committed *beside the code they describe*, and a vault is not where that code lives.
  - **The plugin's procedure moves with the tools.** [workshop-shape](wayfinder/tickets/031-workshop-shape.md) set the seam as *server owns content, plugin owns procedure* — so a tool moving to the CLI **is** a procedure change, and the skills and the reviewer agent are rewritten inside [mcp-diet](wayfinder/tickets/059-mcp-diet.md) rather than in a follow-up that would leave the plugin instructing a tool that no longer exists.
  - **`workshop-drive` blocks the diet, and is not superseded by it.** [workshop-drive](wayfinder/tickets/034-workshop-drive.md) is open on [map-mcp](wayfinder/map-mcp.md) and observes whether whole-document write loses rows and whether the model honours read-before-write — exactly the evidence the diet decision wants. Retiring it because the diet might make it moot would be resolving the decision by declining to gather its evidence.
- **`SPEC.md` is amended as each ticket lands**, per this repo's habit — §1 scope, §9 for whatever the renderer decision does to "pixel-identical", and §10 for every new string. `CONTEXT.md` is maintained as terms sharpen; expect at least **Fence** and **Render** to want entries.
- **Skills:** `/grilling` + `/domain-modeling` for the four decision tickets; `/research` subagents for the two research tickets; `writing-copy` for every user-facing and model-facing string — CLI help text and refusals are copy, and their reader is a developer at a terminal; the `run` skill and the WebKit-checkpoint habit for anything that needs a live look.
- **Tracker (local markdown):** tickets live in `wayfinder/tickets/*.md`. Frontmatter: `status: open|closed`, `assignee` (non-empty = claimed), `blocked-by: [ticket names]`. Frontier = open, unassigned, all blockers closed. Resolutions are appended to the ticket under `## Resolution`, then `status: closed`. Commit tracker changes to `main`.

## Decisions so far

<!-- one line per closed ticket -->

- [does a foreignObject SVG with an embedded font render on github.com?](wayfinder/tickets/049-github-svg-probe.md) — **green, and the committed image stays an SVG**: GitHub does not sanitize committed SVG files (`<script>` payloads return byte-identical, and github/markup#1160's `dominant-baseline` casualty no longer reproduces), and three in-the-wild specimens carrying `foreignObject` plus a base64 `@font-face` render on github.com today at 300+ KB — closing by observation the gap valtio left open. Three constraints ride along: a **nested `<svg>` inside `<foreignObject>` never draws through `<img>`**, which silently costs the collaborator-kind glyphs that are the only visual carrier of SPEC §4.2's closed set and is now [committed-images](wayfinder/tickets/056-committed-images.md)'s first decision; `xmlns` must stay `http:` or the blob view re-serializes the file; and the raw URL is a top-level document where the embedded fonts genuinely are blocked. Plus one scale input — 1440px renders at 0.622 in a README column, putting the smallest label at 5.7px

## Not yet specified

- **Obsidian.** Ruled out above on workflow, not on feasibility — the API fit is the best of any surface. This graduates if canvases turn out to live in a vault after all, and the evidence would be you missing it while using the VS Code one.
- **Publishing, and the rename that rides with it.** `bc-canvas-mcp` stays `private` and the CLI runs from a checkout. The trigger is a **second repo** needing `bcc` in CI — at that point publishing, the `src/lib/model/` lift out of the app, and per-install root parameterization stop being three questions and become one. Note the two rejections this map is holding are both dated: decision 1 deferred publishing to *"three months' real use"* from 2026-08-09.
- **PNG's place once SVG lands.** If [github-svg-probe](wayfinder/tickets/049-github-svg-probe.md) comes back green, PNG is no longer the committed-image answer but is still the answer for non-browser rasterizers, PDF pipelines and anything that is not a web engine. Whether `bcc render --png` ships at all, and whether it is allowed to pull in Playwright for a CLI that otherwise needs only Node, is a question [committed-images](wayfinder/tickets/056-committed-images.md) may hand back rather than settle.
- **Whether the fence earns a live editing surface.** Every rendering here is read-only. If a rendered fence makes people want to edit in place, that is a different product decision touching SPEC §1's "single-document editor" scope, and it opens as a fresh map, not a ticket here.

## Out of scope

- **A terse canvas DSL.** The fence's payload is settled by [fence-shape](wayfinder/tickets/052-fence-shape.md), but a hand-writable DSL is ruled out ahead of it. It is not "a second parser" — it is a **second front door** that six subsystems hang off: `parseCanvasFile` is the single funnel for file import, bundled examples, the JSON View's Apply, MCP read, MCP write and the artifact's embedded block. The refusal contract would fork (SPEC §3.3 promises JSON paths *"written the way a developer would type them"*; a DSL has line and column), migrations are defined as raw-JSON rewrites, and byte-identical round-trip backs autosave, the unexported-changes flag, the artifact embed and the examples pinning test.
- **A hand-written native-`<text>` SVG emitter.** The sheet is a 12-column grid with `subgrid`, eight flex contexts, wrapping message chips and four wrapping prose fields; reproducing that in SVG primitives means measuring text and emitting one `<tspan>` per line. SPEC §9 states one shared read-only `CanvasSheet` is the canonical visual truth so that *"editor and artifacts can never drift visually"* — a second emitter is that drift, made permanent.
- **A hosted render service** (the Kroki pattern). It costs hosting and sends canvas content into a URL, to reach a surface a committed file already covers. GitLab's Kroki integration is additionally unreachable: it is an instance-level admin setting, and the fence names it forwards come from a constant in the asciidoctor-kroki gem, so a self-hosted Kroki serving a custom `bcc` type needs a change to GitLab or the gem.
- **Markdown import.** Unchanged from [map-views](wayfinder/map-views.md): no `.bcc.md` comes back in, ever. A fence that renders is still not a fence that round-trips.
