## Question

The [map's](wayfinder/map-canonical-v5.md) Destination names a three-part gate that no single ticket owns end to end. This is that gate, run once everything else has landed, in the checkpoint habit of [examples-live-checkpoint](wayfinder/tickets/024-examples-live-checkpoint.md) and [mcp-hosts-checkpoint](wayfinder/tickets/030-mcp-hosts-checkpoint.md) — evidence on disk in `.scratch/canonical-v5-checkpoint/`, WebKit via Playwright since safaridriver stays blocked.

**One: a real v1 canvas migrates and round-trips through both surfaces.** Not a fixture written for the occasion — a canvas authored before this map existed, carrying a `relationship` string and a bare-name collaborator. It must load in the app, load through the MCP server, and produce byte-identical v2 output from both. The two share `$lib/model/parse` so this should hold by construction; the point of running it is that "should hold by construction" is exactly the claim this map was created to stop making without checking.

**Two: the four examples are byte-exact at v2** through the shipped path, and a v2 HTML artifact's embedded canvas is byte-identical to the same canvas exported as `.bcc.json` (`SPEC.md:278`).

**Three: the rendered sheet, held beside a printed V5, shows the same ten panels.** This is the human half and the one that closes the Destination — the whole map exists because nobody had ever done this comparison. Render a full canvas, put it next to `resources/bounded-context-canvas-5v-blank.jpg`, and walk the ten panels. Then walk the six adopted changes and confirm each is actually there and reads as intended: `Purpose` on the panel and in the file, classification as a tenth panel with its three sub-columns, the centre column's shared box, a kind icon on every collaborator with the footer legend keying all four, both relationship ends with the ink-weight convention keyed in that same legend, and the caution ring on an anti-pattern trait. The PNG and the HTML artifact both, since the sheet is mounted offscreen for each.

**And confirm the tin is now true.** `SPEC.md:3` claims the V5 canonical layout and the title block stamps `Bounded Context Canvas · V5`. If anything found here still contradicts that, it is either fixed or written down — this map does not close with an undocumented departure in it, which is the failure it was chartered to end.

## Resolution

**Resolved 2026-08-11. All three parts green, and the tin is true.** Run on Playwright WebKit against the local production build (`npm run build` + `vite preview`) and the rebuilt `mcp/dist/server.js` — local rather than the live origin because `main` is thirteen commits ahead of `origin/main`, so `bc-canvas.pages.dev` still serves v1. The gate exercises the shipped bundle either way; the deploy is one push, left to Mitchell with the sign-off. Scripts and evidence in `.scratch/canonical-v5-checkpoint/` (`checkpoint.mjs`, `side-by-side.mjs`, `evidence/` with the exports, screenshots, the v1 digest and `checkpoint.json`).

**One: the real v1 canvas migrates and round-trips through both surfaces.** The specimen is `.scratch/mcp-hosts-checkpoint/host-drive/canvas-editing.bcc.json` — drafted 2026-08-09 by the hosts checkpoint, before this map existed, eight lanes all carrying v1 `relationship` strings and every collaborator a bare name. Through the app's real Import… it lands clean and renders all ten panels, `brain context` in the caution ring and every migrated value on the `ours` side of a one-sided arrow; the export is v2 — `purpose` present, `description` gone, every collaborator and relationship an object — and the HTML artifact embeds those exact bytes. Through the built server it lists without problems, the digest speaks the v2 idiom (`## Purpose`, `## Strategic classification` as a section, the migrated value on the pair line), and `view: "json"` stays the bytes on disk. The server's written bytes equal the app's export plus the §3.5 trailing newline — **byte-identical v2 across the two surfaces** — and its digests of the v1 file and the written v2 file are identical strings, so both loads land on one structure. "Should hold by construction" held, and is now checked rather than claimed.

**Two: the four examples are byte-exact at v2 through the shipped path.** Each opened from the chooser and exported: byte-identical to its committed file up to the committed trailing newline (SPEC §3.5's one allowed difference), `version: 2` in every export, and each HTML artifact's embedded canvas block equals the committed bytes exactly.

**Three: the sheet beside the printed V5 shows the same ten panels.** `evidence/side-by-side.png` holds upstream's `bounded-context-canvas-5v-blank.jpg` beside the shipped PNG export of Order Fulfillment, and the walk ran on both the PNG and the opened HTML artifact, since the sheet mounts offscreen for each. The two departures still visible are the recorded ones — the `Collaborator`/`Messages` column heads the mockup dropped, and the unmirrored outbound lanes ruled out of scope.

**And the tin is true.** `SPEC.md:3` claims the V5 canonical layout; the title block stamps `Bounded Context Canvas · V5`; after this walk both say what the shipped thing does, with every remaining difference written down where it was decided.

**One finding, fixed here.** `bcc_write_canvas`'s `version` parameter said it exists "only so a document read with `view: "json"` can be handed straight back" — false for exactly the files where version matters: a v1 document handed straight back is refused field by field at the schema layer (the refusals are in `checkpoint.json`), and nothing on that path said so. The sentence now carries the constraint and the remedy: only a document already at the current version can be handed back; an older one is refused, naming each field that has to change. That the write path teaches v2 rather than accepting v1 shapes stays as designed — migration belongs to the readers, not the wire format. Bundle rebuilt; suites 339 + 91 green, `tsc` clean.
