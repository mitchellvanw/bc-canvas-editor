## Question

The map's destination, run against the shipped result rather than asserted from the tickets. Per the checkpoint habit, every leg produces evidence in `.scratch/render-checkpoint/` and a red leg goes back to the ticket that owns it rather than being patched here.

1. **Identity — the leg this map exists to protect.** The sheet `bcc render` produces and the sheet the editor exports are the **same sheet**, on all four committed examples. Bytes where bytes can be equal; a pixel comparison where they legitimately cannot, since SSR emits hydration comments client `innerHTML` does not. Read the editor's side back through a real browser rather than reasoning about it — the precedent is [views-checkpoint](wayfinder/tickets/048-views-checkpoint.md), where the artifact leg was only honest because it was read back through a DOM. **Build a fifth specimen if the four examples do not exercise the transformation**, exactly as 048 had to when none of the four contained a `<`, `>` or `&`.
2. **GitHub.** A canvas committed in a repo renders in a markdown file on github.com — the real surface, not a local replay of its headers, which is the gap [github-svg-probe](wayfinder/tickets/049-github-svg-probe.md) was created to close. Fonts as decided in [committed-images](wayfinder/tickets/056-committed-images.md).
3. **VS Code.** A `bcc` fence renders in the markdown preview on a real repo, and a canvas edited underneath behaves as [vscode-extension](wayfinder/tickets/058-vscode-extension.md) decided.
4. **A unified-based site.** The remark plugin renders on at least two targets from a real build.
5. **No browser in the chain.** `bcc render` produces its HTML and its committed image with Node alone — no Playwright, no Chromium — unless [committed-images](wayfinder/tickets/056-committed-images.md) knowingly bought one for PNG, in which case the SVG path still runs without it.
6. **Round trip.** A canvas written by the CLI opens unchanged in the editor, and a canvas exported by the editor is read unchanged by the CLI. The property [mcp-hosts-checkpoint](wayfinder/tickets/030-mcp-hosts-checkpoint.md) established for the server, re-run for the surface that has joined since.
7. **Staleness.** The mechanism [committed-images](wayfinder/tickets/056-committed-images.md) chose actually catches a stale image — change a canvas, do not regenerate, and confirm the check fails. A freshness guarantee nobody has tried failing is a comment.
8. **The MCP surface after the diet.** `tools/list` re-measured against the rebuilt bundle, the plugin's skills driven once in Claude Code to confirm they instruct tools that exist, and the resource still reachable.
9. **Both suites plus `svelte-check` green**, with the MCP bundle rebuilt if anything under `src/lib/` moved.

Green here reaches the destination and closes the map. What a red leg forces goes back on the map before anything else is built.

## Resolution

**Eight legs green, one green with a red rider — and the rider is a new frontier ticket, so the map does not close today.** Evidence in `.scratch/render-checkpoint/` (probe scripts and the decisive artifacts committed, per the checkpoint habit).

1. **Identity — green, on five specimens.** None of the four examples contains a `<`, `>` or `&` — the exact gap [views-checkpoint](wayfinder/tickets/048-views-checkpoint.md) hit — so 048's own edge canvas ("Angle & Script `<edge>`", with a literal `</script>` and a literal `&amp;`) became the fifth, run through `bcc fmt` first. For each of the five: Import… into the live editor (Playwright WebKit on the production build), Export → HTML artifact, download bytes captured through the page — **byte-identical to the `.bcc.html` the CLI wrote from the same canvas, all five** (222,174 / 216,684 / 214,966 / 226,257 / 214,856 B). The pixel-comparison clause was never needed: the export goes through the committed render module, and the bytes prove it end to end.
2. **GitHub — green on the surface, red in Safari at README scale.** The real github.com serves the committed bytes exactly (206,623 B, `image/svg+xml`, naturalWidth 1440 × 1292) and Chrome draws the whole sheet — fonts, collaborator-kind glyphs, frame ([056](wayfinder/tickets/056-committed-images.md)'s xmlns fix live). **WebKit at the README's 758px renders Business Decisions, Assumptions, Verification Metrics and Open Questions as empty panels** — bisected to a minimal repro: WebKit's SVG-as-image display path paints `position: relative` foreignObject content **unscaled** when the image displays below natural size, and `.stack li` is exactly `position: relative` (`CanvasSheet.svelte:975`). At natural size WebKit is correct; `drawImage` to a canvas is correct at every size; Chrome is correct everywhere. Goes forward as [webkit-svg-stacks](wayfinder/tickets/063-webkit-svg-stacks.md) rather than being patched here.
3. **VS Code — green, on 058's harness.** Two sheets and three placeholders in the real workspace's preview, tiers armed (`container-type: inline-size`), six faces loaded from `data:` alone, no CSP banner. The watcher both ways: an on-disk rename redrew the sheet without the markdown being touched, and creating the missing canvas healed its placeholder into a third sheet — [058](wayfinder/tickets/058-vscode-extension.md)'s heal-on-write, observed.
4. **Unified sites — green, from today's build.** [057](wayfinder/tickets/057-remark-plugin.md)'s Astro and Docusaurus scaffolds reinstalled from a fresh `npm pack` and rebuilt: Astro zero-config draws the sheet (1424×1191, Archivo 38.4px, isolation intact both ways) plus [052](wayfinder/tickets/052-fence-shape.md)'s placeholder for the broken fence; Docusaurus `.md` and `.mdx` both draw at the docs column's 823px — the tiers reflowing.
5. **No browser — green, proved outside the checkout.** A zero-dependency tarball install (node_modules holds exactly this package; a first in-repo attempt was discarded — Node resolution walks up and finds the repo's own playwright-core): `check` redraws and byte-diffs all four images, `render` writes all four artifacts, `render --svg --height` reproduces **byte-identical committed SVGs**, all in plain Node; without `--height` the refusal is a sentence, not a crash. Where a browser was reachable, the measured render also came back byte-identical — declared and measured heights agree.
6. **Round trip — green at the canvas level, one byte short at the download.** All five fmt-canonical files open clean (no Unexported changes, Undo disabled); all five editor exports pass `bcc check` and re-import identically. But the editor's Canvas-file download is `serializeCanvas` — **no trailing newline** — where `canvasBytes` says the newline "is part of what the file format is" (SPEC §3.5): `fmt` rewrites every editor-exported file once, by one byte. Goes forward as [export-trailing-newline](wayfinder/tickets/064-export-trailing-newline.md).
7. **Staleness — green, by failing it.** Edit a canvas, skip the regenerate: `check` exits 1 naming the file and the redraw command; regenerate: exit 0; mistyped flag: exit 2 — [055](wayfinder/tickets/055-bcc-cli.md)'s three-code contract observed live from a hook's point of view.
8. **MCP after the diet — green, measured and driven.** The committed bundle over stdio: exactly two tools, tools/list at 1,557 chars ≈ 389 tokens (the diet's 433 ballpark; nothing crept back), `resources/list` still four concrete URIs, the resource readable. Driven once in real Claude Code (`claude -p --plugin-dir mcp/`, scratch project, `bcc` from the zero-dep install): draft-canvas-from-code ran end to end with zero tool errors — `bcc_explain` ×7, `bcc_read_canvas` ×2, `bcc ls`/`bcc fmt` — and the draft passes `check` with the judgment sections left as open questions. No plugin doc names a departed tool.
9. **Suites — green.** Root 506/506, MCP 36/36, `svelte-check` 0/0, and all three package `tsc` checks; the committed bundles' staleness tests ride inside those suites, so the bundles are current by the same evidence.

[cli-refusal-register](wayfinder/tickets/065-cli-refusal-register.md).
