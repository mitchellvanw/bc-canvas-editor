# Wayfinder map: the canvas leaves the browser

## Destination

A canvas committed in a repo **renders in a markdown file** — on GitHub through a committed `.bcc.svg`, and in VS Code's preview through a `bcc` fence — from **one renderer that runs in Node with no browser**. `bcc render`, `check`, `fmt` and `ls` drive it from a checkout. The MCP surface has been re-sized with [workshop-drive](wayfinder/tickets/034-workshop-drive.md)'s evidence in hand. And the byte-identity property holds: **the sheet the CLI renders and the sheet the editor exports are the same sheet**, proved on all four examples, not asserted.

## Notes

- **This map carries execution**, like the hosting, examples, canonical-v5 and views maps before it. The product is shipped and live; these are increments on it, so task tickets *do* — build, render, rebuild — once the decision and research tickets clear.
- **The finding this map is built on, established before charting (2026-08-13):** `CanvasSheet.svelte` renders through Svelte 5's `svelte/server` `render()` in plain Node — no DOM, no jsdom, no headless Chromium — and the result is pixel-faithful. It works because the sheet uses **zero Tailwind utility classes except `sr-only`**: all 551 lines of its styling are Svelte-scoped CSS reading 26 custom properties, every one declared in the single `@theme` block in `src/app.css`. Measured: 31.8 KB standalone without fonts, 204 KB with 8 WOFF2 faces base64'd from disk, against ~446 KB for the browser export (which inlines the entire compiled stylesheet — Tailwind preflight, every utility, and the scoped CSS of Chrome, EditableSheet, Picker, JsonView — to render a read-only sheet). This retires `mcp/README.md`'s standing claim that writing an artifact *"would mean rendering the sheet, which needs a browser."* Probe scripts in `.scratch/helicopter/`.
- **Settled context (from charting, 2026-08-13):**
  - **Both asks are in scope.** "Renders like mermaid" was two asks wearing one sentence — *renders while I write* (an editor extension point) and *renders in the repo* (a committed image plus a build-time plugin). The map takes both. They share almost no implementation, which is why they are separate tickets rather than one.
  - **GitHub has no fence route, for anyone.** Its supported list — mermaid, GeoJSON, TopoJSON, ASCII STL — has no registration mechanism behind it, and inline `<svg>` in markdown is dropped whole (the sanitizer's allowlist carries `img` and no `svg`, no `foreignObject`, no `style`). The committed image is not a compromise reached after trying; it is the only surface that exists.
  - **The committed image is an SVG, not a PNG** — settled green by [github-svg-probe](wayfinder/tickets/049-github-svg-probe.md), and **amended by [committed-images](wayfinder/tickets/056-committed-images.md), which found the no-browser half of this too strong.** A `foreignObject` SVG wraps *the same HTML the headless renderer already emits*, but the SVG root needs a height and nothing headless can measure one, so **authoring** an image drives an already-installed Chrome. What survives, and is the stronger claim anyway, is that **the staleness check runs in plain Node** — it reproduces at the height the file declares and diffs the bytes — where a PNG's check could never be anything but a rasterization. The renderer itself is unchanged: still Node, still no browser. It is also ~10× cheaper in the repo: the font payload is byte-identical across canvases, so git's delta compression collapses it (152 KB for four sheets against 1,472 KB of PNG). PNG stays available for anything that is not a web engine.
  - **Claude Desktop is out of scope for now** — a scoping call on current use, explicitly not "Desktop is dead". It was the entire justification for a server over a skill-plus-CLI ([mcp-server-shape](wayfinder/tickets/025-mcp-server-shape.md) decision 3: *"The server wins on reach… If Claude Code were the only target, the skill would be the right answer."*). With it out, the diet ticket is allowed to propose moving writing and listing to the CLI. If Desktop comes back, that ticket's answer is what gets revisited, not this map's destination.
  - **The CLI is unpublished but not repo-local** — amended by [cli-home](wayfinder/tickets/051-cli-home.md), which found this line half wrong. `bcc` runs from a foreign checkout through `npx --yes github:mitchellvanw/bc-canvas-editor`, because [committed-images](wayfinder/tickets/056-committed-images.md)'s staleness guard needs something a hook in another repo can call. [mcp-server-shape](wayfinder/tickets/025-mcp-server-shape.md) decision 1 survives *literally* rather than by charity: `private` blocks `npm publish` and measurably does not block a git install, so no registry name is claimed, no semver contract exists, and a caller wanting reproducibility pins a SHA itself.
  - **`src/lib/model/` does not move.** [mcp-server-shape](wayfinder/tickets/025-mcp-server-shape.md) decision 5 rejected lifting it to a neutral top-level package as *"a rename touching most of the app, SPEC's file map and every test"* — rejected when the model layer had one consumer. This map takes it to four or five, and the answer is unchanged: because every new consumer is repo-local (above), each reaches the model through the same `$lib/*` alias `mcp/tsconfig.json` already uses, and the rename buys nothing until something is published to somebody else.
  - **VS Code, not Obsidian.** Obsidian is the cleanest API fit in the survey — `registerMarkdownCodeBlockProcessor` hands you a div and expects arbitrary DOM, mapping 1:1 onto `src/lib/artifact/offscreen.ts`'s existing `mount(CanvasSheet, …)`. It is also the worst workflow fit: [mcp-server-shape](wayfinder/tickets/025-mcp-server-shape.md) decision 2 fixed the model as canvases committed *beside the code they describe*, and a vault is not where that code lives.
  - **The plugin's procedure moves with the tools.** [workshop-shape](wayfinder/tickets/031-workshop-shape.md) set the seam as *server owns content, plugin owns procedure* — so a tool moving to the CLI **is** a procedure change, and the skills and the reviewer agent are rewritten inside [mcp-diet](wayfinder/tickets/059-mcp-diet.md) rather than in a follow-up that would leave the plugin instructing a tool that no longer exists.
  - **`workshop-drive` blocked the diet, and was not superseded by it — now closed, with both pieces of evidence delivered.** [workshop-drive](wayfinder/tickets/034-workshop-drive.md) on [map-mcp](wayfinder/map-mcp.md) observed whether whole-document write loses rows and whether the model honours read-before-write — exactly the evidence [mcp-diet](wayfinder/tickets/059-mcp-diet.md) wants — and both came back **green** over one real facilitated session (six writes, +79 rows, nothing lost; 6 writes against 7 reads, perfectly alternating). Retiring it because the diet might make it moot would have been resolving the decision by declining to gather its evidence; instead the diet inherits a surface whose write path has been shown safe, so nothing in these findings argues for keeping the server on account of write safety. It closed on **Leg A alone** by Mitchell's call (2026-08-14), which costs the diet nothing — Leg B carried the Desktop root story, and Desktop is already out of scope here — but does leave observation 6 unobserved, so whether `review-canvas` is two entry points or one plus a corpse arrives at the diet as an open question rather than a checked one.
- **`SPEC.md` is amended as each ticket lands**, per this repo's habit — §1 scope, §9 for whatever the renderer decision does to "pixel-identical", and §10 for every new string. `CONTEXT.md` is maintained as terms sharpen; expect at least **Fence** and **Render** to want entries.
- **Skills:** `/grilling` + `/domain-modeling` for the four decision tickets; `/research` subagents for the two research tickets; `writing-copy` for every user-facing and model-facing string — CLI help text and refusals are copy, and their reader is a developer at a terminal; the `run` skill and the WebKit-checkpoint habit for anything that needs a live look.
- **Tracker (local markdown):** tickets live in `wayfinder/tickets/*.md`. Frontmatter: `status: open|closed`, `assignee` (non-empty = claimed), `blocked-by: [ticket names]`. Frontier = open, unassigned, all blockers closed. Resolutions are appended to the ticket under `## Resolution`, then `status: closed`. Commit tracker changes to `main`.

- [does a foreignObject SVG with an embedded font render on github.com?](wayfinder/tickets/049-github-svg-probe.md) — **green, and the committed image stays an SVG**: GitHub does not sanitize committed SVG files (`<script>` payloads return byte-identical, and github/markup#1160's `dominant-baseline` casualty no longer reproduces), and three in-the-wild specimens carrying `foreignObject` plus a base64 `@font-face` render on github.com today at 300+ KB — closing by observation the gap valtio left open. Three constraints ride along: a **nested `<svg>` inside `<foreignObject>` never draws through `<img>`**, which silently costs the collaborator-kind glyphs that are the only visual carrier of SPEC §4.2's closed set and is now [committed-images](wayfinder/tickets/056-committed-images.md)'s first decision; `xmlns` must stay `http:` or the blob view re-serializes the file; and the raw URL is a top-level document where the embedded fonts genuinely are blocked. Plus one scale input — 1440px renders at 0.622 in a README column, putting the smallest label at 5.7px

- [what does VS Code's markdown preview allow a markdown-it plugin to emit?](wayfinder/tickets/053-vscode-preview-spike.md) — **the pointer fence stands**: a synchronous disk read works inside a *renderer* rule because `extendMarkdownIt` runs in the extension-host process with full Node, never in the webview, and three shipped extensions rely on the same path. No sanitizer — inline `<style>`, inline `<svg>`, custom attributes and the sheet's `subgrid` plus `@container` tiers all survive and compute — with one exception that is a CSP block rather than a strip: an inline `<script>` never runs **and** raises the "Some content has been disabled" banner, so the rule is never emit one. Fonts work by all three routes, but `localResourceRoots` (not CSP) is the constraint, so an extension contributing only `markdownItPlugins` cannot serve a file from its own directory. Two limits recorded rather than discovered later: resolution must happen at render because `env.currentDocument` is `undefined` at parse and parse output is cached, and **a fence in a notebook cell will never resolve a pointer**

- [what shape is the headless renderer, and does it replace the browser export?](wayfinder/tickets/050-renderer-shape.md) — **one renderer, built once into a plain-JS module every consumer imports — the CLI, the remark plugin, the VS Code extension and the editor's own Export HTML**, which makes the map's byte-identity property structural rather than tested-for. It **replaces** the browser export, because a normalized SSR-vs-`innerHTML` diff came back agreeing on everything visual (scoped class hashes identical) and disagreeing byte-wise in three mechanical ways — comment markers, entity escaping, attribute order inside the one dynamic `<svg>` — so "sit beside it, with a test that proves the two agree" could only ever be a test that *licenses* drift. It emits **a core returning parts plus thin named containers** (`renderSheetParts`, `fontFaceCss`, `sheetDocument`/`sheetSvg`, `artifactDocument`), because the fragment a fence needs is not a document with options switched off. `sr-only` moves into `CanvasSheet.svelte`'s own `<style>` so the sheet is self-contained by construction; tokens are parsed from `app.css`'s `@theme` (the idiom two tests already use) and land on the sheet's **wrapper**, never `:root`, so a fence cannot repaint its host document; fonts are always inlined in the file containers with de-duplication left expressible rather than flagged; input is a `CanvasDoc`. Home is `src/lib/render/`, built like `mcp/` — committed module, staleness test — because `vite-plugin-svelte` derives `generate` from Vite's SSR flag and one build cannot emit both compiles. `collectAppCss()`'s runtime fetch dies with it, retiring SPEC §13's noted risk; `offscreen.ts` survives, because PNG still rasterizes a live mount. The `.woff` win is not independent as charted — it evaporates into the renderer, which authors the `@font-face` rules rather than rewriting fontsource's

- [where does the bcc CLI live, given mcp/ is the plugin root?](wayfinder/tickets/051-cli-home.md) — **`cli/` at the repo root, a directory of the root package rather than a third package**, with its `bin` on the root `package.json` and its bundle committed and self-contained. The ticket's four-option list was the wrong axis: the real fork was **whether `bcc` ever runs outside this checkout**, and it does — which forced the rest. Four probes decided what recollection would have got wrong: `private: true` does **not** block a git install (so decision 1 survives literally); `prepare` **never runs** under npm 11's `allow-scripts` gate and drags the full devDep tree under npm 10, so an install-time build is version-dependently broken and the bundle **must** be committed; a git install carries the **whole repo** absent a `files` field; and npm's `#path:` subdirectory spec is a **trap** — it reads the subdirectory's name and deps but installs the root's tree and manifest, so a `bin` under `mcp/` would never be found. Also measured: npm does not link a package's own bin, so the `bin` is inert locally and `npm run bcc --` is the everyday form. `cli/build.js` **inlines the committed renderer module** rather than re-compiling the sheet — the one decision the map's byte-identity gate rests on — at the price of the fonts' ~200 KB living in two committed bundles, and three bundles now under byte-diff with a rebuild order to enforce. The filesystem cluster lifts to `src/lib/fs/` with `canvasBytes` going to `src/lib/model/` instead (it is the serializer plus a newline, never a filesystem concern), which costs `"types": ["node"]` on the root tsconfig; containment **survives with its justification rewritten** — not a security seam against an untrusted proposer, but the bound on the walk `ls` and `fmt` need. `mcp/` is not frozen for [workshop-drive](wayfinder/tickets/034-workshop-drive.md), which measures model behaviour through the tool surface and cannot see a moved import

- [what goes in a bcc fence, and what comes out of it](wayfinder/tickets/052-fence-shape.md) — **one path to a Canvas file, resolved relative to the markdown file that holds it, rendered as the Sheet alone.** The fence writes no resolution logic: `readCanvas` already *is* containment-then-read-then-parse returning a closed refusal union, and `readProblem` already *is* the path-first sentence a placeholder wants — which amends [fs-seam](wayfinder/tickets/061-fs-seam.md) to carry `read.ts` and `readProblem` across the seam too (`readRefusal` stays behind, MCP-shaped down to `isError`). Inline JSON is refused: it has no reconciliation story, and on any surface that does not know the fence its *content* is what a reader sees — a path is a readable fallback where 3.8 KB of `&lt;`-escaped JSON is a wall. That costs notebooks, permanently and by name. `bcc` is confirmed as the info string, a tail after it is **refused rather than ignored** so the grammar stays genuinely open, a leading `/` is refused as one syntax carrying two meanings, and a pointer may name anything `readCanvas` accepts — including a `.bcc.html` artifact, because a rule living only in the fence is a rule two adapters will eventually disagree about. Failure is one shape everywhere: a **visible, preamble-free placeholder** — never silence, and never depending on the preamble that may be what failed — with `detail` on the adapter's warning channel rather than the page, keeping SPEC §3.3's rule by its reasoning (the offending bytes are in another file) rather than its letter, and **the build never fails**, because escalation belongs to the site. `fontFaceCss()` is hoisted once per document, which is [renderer-shape](wayfinder/tickets/050-renderer-shape.md)'s de-duplication finally exercised and not optional: `localResourceRoots` forces base64 fonts, so three self-contained fences would be 600 KB per keystroke

- [the renderer leaves the browser — one sheet, rendered in Node](wayfinder/tickets/054-headless-renderer.md) — **built, and the gate property is demonstrated rather than asserted**: the `.bcc.html` Chromium downloads from the live editor is byte-identical to the one Node writes from the same module, 225,907 bytes both ways. `src/lib/render/` is five files — an entry never imported from source, a Vite SSR build pinned to `NODE_ENV=production` (vitest sets `test`, which the Svelte compiler reads as dev mode and answers with an 82 KB larger module), a committed 275 KB bundle with zero imports, a typed facade, and the `SHEET_WIDTH`/`SHEET_MARGIN` pair lifted off `offscreen.ts` so the page frame and the PNG mount cannot disagree. The artifact fell from ~446 KB to 225,907 B, `collectAppCss`/`inlineFonts`/`fetchAsset` are gone with jsdom and the fetch mock, and the `.woff` win needed no fix — authoring the `@font-face` rules never names the legacy files. Eight decisions 050 did not make, of which three matter: the core **emits its own wrapper** (050 put the tokens on "the wrapper that already carries `paper-ground`", but that wrapper only exists in a document and the fragment consumers compose parts with no container in between), the artifact **neutralises that wrapper's ground with one rule** (a second painting restarts the 32px grid at the wrapper's origin — a visible seam, not a theoretical one), and **a scoped preflight ships in the renderer's CSS** (the sheet takes border-box and the absence of UA margins from Tailwind and never restates them). `sheetSvg` takes its size from the caller because laying the sheet out is exactly what a headless renderer does not do. Rendered through `<img>`, it draws — and the four collaborator-kind glyphs are missing, which is [github-svg-probe](wayfinder/tickets/049-github-svg-probe.md)'s nested-`<svg>` finding reproduced first-hand on our own output

- [the committed .bcc.svg, and what keeps it current](wayfinder/tickets/056-committed-images.md) — **a `<name>.bcc.svg` beside its canvas, kept current by re-rendering it and diffing the bytes**. The ticket's hardest question was one it never asked: `sheetSvg` takes its height from the caller and nothing headless can supply it — the 049 probe launched Chromium for it. The answer splits the two jobs, **a browser measures and Node reproduces**, after which the staleness guard needs neither: it parses `height="…"` out of the file under test, re-renders and byte-diffs, because the declared height is only ever used to *reproduce* a render then judged by comparison, and clipping can never persist silently since content growth fails the diff first. That is `server.test.ts`'s mechanism on a second artifact, and it is the asymmetry that keeps SVG ahead of PNG now that authoring admits a browser — **SVG's check runs in plain Node; PNG's never could**. **049's first constraint was misdiagnosed**: a nested `<svg>` draws fine inside `<foreignObject>` provided it carries `xmlns` — the content is XHTML, so an undeclared `<svg>` inherits XHTML and is not a drawing — so the collaborator-kind glyphs cost one attribute on `CanvasSheet.svelte:130` rather than a rewrite, while every `data:` URI route (`background-image`, `<img>`, `content:`) renders *nothing* under the same sandbox rule that forces the fonts to be embedded. A second live drift fell out: `FRAME_CSS` claims to be "the page frame both file containers draw the sheet in" and `sheetSvg` does not use it, so the SVG lays out at 1440 where every other surface uses 1360 — fixed, and the width stays `SHEET_WIDTH` because ~1100 would get the desktop grid squeezed into a width nothing was drawn for, the tiers being inert here. Path-general and committed, because [cli-home](wayfinder/tickets/051-cli-home.md)'s foreign-`npx` reach exists for exactly this hook; `svg` joins `ExportKind` and SPEC §3.4 **one-way**, the editor gaining "SVG image" fourth in the menu since it measures for free; `bcc render --svg` drives an *already-installed* Chrome via `playwright-core` `channel:'chrome'` — 3 MB, no browser download — with `--height` as the escape hatch. An absent image is silent and an unparseable one is a refusal rather than "stale"; nothing in the image claims freshness, because a stamp would render on every surface including the live editor, and the README's image links to its `.bcc.json` instead

- [the filesystem seam — one cluster, two callers](wayfinder/tickets/061-fs-seam.md) — **moved, with the exact 31 tests it counted and no behaviour change anywhere**: `root.ts`, `discover.ts`, `read.ts` and `writeAtomic` into `src/lib/fs/`, `canvasBytes` into `src/lib/model/serialize.ts`, `mcp/` reaching all of it through the `$lib/*` alias it already resolved. Both frictions it flagged came in at the size it guessed — `conditions: ['browser']` a non-issue, `"types": ["node"]` one line — and `vite build` pulls no builtin into the client bundle, because nothing reachable from the app imports the cluster. **The rebuilt bundle is the real proof, and a stronger one than the byte-diff test it was chartered as**: an *order-insensitive* diff of the old and new 1.2 MB files comes back as exactly the two rewritten strings plus the `// ../src/lib/fs/*.ts` path comments — not one other line moved, which is "nothing else changed" as a property rather than a green tick. Four calls the ticket left implicit: `readProblem` landed **in** `read.ts` (it and `readCanvas` are one import for every caller with a path and a surface to write on — both fence adapters take exactly that pair); `canvasBytes` went **into** `serialize.ts` rather than a one-function sibling, its two tests joining `serialize.test.ts`; `readProblem`'s `newer-version` sentence was rewritten **too**, beyond the one string named, since *"this server reads up to version 2"* is the identical fault in a function crossing the same seam in the same commit — now *"version 2 is the newest that can be read here"*, while `readRefusal`'s copy stays server-voiced because only a write surface can promise *"nothing was changed"*; and `OutsideRoot` keeps its subject and loses its actor. Containment's justification is rewritten per [cli-home](wayfinder/tickets/051-cli-home.md) decision 9, and the honest version is **narrower than "not a security seam"** — it is the bound on the walk, because `findCanvases` needs to know where to stop and `relative()` needs a base to name against; `/` is the proof it is not a lock, since a caller that wants the whole disk opens it and gets it. The tests did not change and did not need to: traversal, absolute paths and symlinks are how a walk leaves its bound *by accident*, which is now the only way it happens. `whyUnservable`'s `--root` sentence looked like the same problem and was not — `bcc` takes the server's own flag, and a fence cannot reach `/` — a string being audience-neutral when it is true for every audience rather than when it names none. **Two blocking edges were missing**: [remark-plugin](wayfinder/tickets/057-remark-plugin.md) and [vscode-extension](wayfinder/tickets/058-vscode-extension.md) each said in prose that this ticket lands first, and a dependency written only in a body never reaches the frontier query

- [bcc — render, check, fmt, ls](wayfinder/tickets/055-bcc-cli.md) — **built, and the map's gate came out as a number**: the `.bcc.html` the CLI writes from a scratch directory with nothing installed beside it is **225,907 bytes**, the same figure [headless-renderer](wayfinder/tickets/054-headless-renderer.md) measured for the file Chromium downloads from the live editor. `npm pack` carries three files and a foreign install pulls **zero dependencies**, which is [cli-home](wayfinder/tickets/051-cli-home.md)'s decisions 3, 4, 6 and 11 landing as written. Nine calls the ticket left open, of which three matter: `render` writes **`artifactDocument`, not `sheetDocument`** — discovered when `bcc check` refused the file `bcc render` had just written, one command later, because a bare sheet page carries no embedded Canvas file and `.bcc.html` is a family member with a contract; `playwright-core` is a **devDependency and a lazy import** rather than the dependency 056 handed forward, because only *measuring* needs a browser and `render --svg --height`, `check` and everything else run in a bare install; and the output name is the canvas's **stem**, never `exportFileName`'s slug of its *name*, or renaming the context inside a file would move the image out from under the staleness check. - [one remark plugin, every unified-based site](wayfinder/tickets/057-remark-plugin.md) — **built, and both targets render from a real `npm pack` install: Astro with nothing configured, Docusaurus with two things and neither of them guessable.** MDX has no raw HTML at all (`Cannot handle unknown node 'raw'`, `.md` and `.mdx` alike, fixed site-side with `rehype-raw` and MDX's five passed-through node types) — and then the plan broke on something the ticket could not have predicted: **React's server render escapes the text inside `<style>`**, and `<style>` is a raw-text element the parser never un-escapes, so the sheet came out **in Times** with `'Archivo'` as `&#x27;Archivo&#x27;` and every attribute selector and `>` combinator in its 15 KB of scoped CSS with it. No adapter can dodge that — the quotes are `CanvasSheet.svelte`'s own — so the ticket's open question, *where a unified pipeline can put a preamble at all*, is answered **both**: `remark/dist/sheet.css` falls out of the same build from `fontFaceCss()` and `renderSheetParts()`, and `{ css: 'imported' }` suppresses the inline one. Inline stays the default because an unstyled sheet is the silent-wrong-render [fence-shape](wayfinder/tickets/052-fence-shape.md) refused, and a zero-config install has to work. The plugin itself holds almost nothing: **`src/lib/fence/fence.ts` is the new home of everything 052 settled**, so [vscode-extension](wayfinder/tickets/058-vscode-extension.md) writes an adapter rather than a second implementation — 052's own argument taken literally. `readProblem` gained two levels of disclosure, and the deciding argument was not tidiness but that `unreadable`'s detail is the filesystem's message and `outside-root`'s is the root's name, so a placeholder carrying either **publishes the author's absolute paths** on a built site; that corrects the doc comment [fs-seam](wayfinder/tickets/061-fs-seam.md) wrote one ticket after 052 said the opposite. The CSS hoist is pinned rather than assumed (all four examples, 15,312 identical bytes, sparse one included), isolation was measured in both directions in the built pages, and **neither host prints VFile messages** — so `detail` reaches nobody there and the README says so instead of implying a channel that is usually deaf. Eleventy, the third name, is markdown-it rather than unified and is not a remark host at all

- [the bcc fence in VS Code's markdown preview](wayfinder/tickets/058-vscode-extension.md) — **built, and the second adapter is 250 lines with the fence in none of them**: the sheet draws in a real project's preview, fonts loaded from `data:` alone, the `@container` tiers reflowing with the pane, and a canvas edited on disk re-drawing the sheet without the markdown being touched. `vscode/` is the repo's second standalone package, because a `.vsix` is packed from a directory whose `package.json` *is* the manifest — everything else copies `cli/` and `remark/` (renderer inlined, bundle committed, staleness test, fourth in `build:bundles`), except CommonJS, because VS Code loads an extension with `require`. **The ticket's cascade question was settled by a diff rather than a reading**: 37 computed properties per element in the preview against the same markup on a bare page comes back with **51 differences** unmitigated — all 44 headings on `line-height: 1.25`, a line drawn under the canvas name by `h1 { border-bottom }`, both footer links stripped of their underline — and **zero** with six declarations, rolled back with `revert` because that lands on the UA origin, which is the origin the sheet was drawn against. `margin` is pointedly not among them ([headless-renderer](wayfinder/tickets/054-headless-renderer.md)'s preflight already holds it at the same specificity), and the inherited `word-wrap: break-word` is turned off rather than kept, since a defect that hides on one surface is worse than one had everywhere. Being the second caller broke two things in the shared contract and both were the contract's fault: `root` and `document` became one `location`, killing a state that was never legal, and `FenceResult` now reports the path it pointed at — needed by the watcher, and reported for the *failing* case too, which is what makes a fence pointing at a file you have not written **heal when you write it**. ## Not yet specified

- **Obsidian.** Ruled out above on workflow, not on feasibility — the API fit is the best of any surface. This graduates if canvases turn out to live in a vault after all, and the evidence would be you missing it while using the VS Code one.
- **Publishing, and the rename that rides with it.** `bc-canvas-mcp` stays `private`. [cli-home](wayfinder/tickets/051-cli-home.md) sharpened this without firing it: `bcc` now reaches a foreign checkout by **git install**, which is measurably not blocked by `private`, so the trigger keeps its meaning — a **registry package** is still the thing that hasn't happened, and a **second repo** needing `bcc` in CI is still what would make it happen. At that point publishing, the `src/lib/model/` lift out of the app, and per-install root parameterization stop being three questions and become one. Watch for the side door: release tags a foreign hook depends on *are* a versioning contract, and [cli-home](wayfinder/tickets/051-cli-home.md) decision 12 declined them for that reason. Note the two rejections this map is holding are both dated: decision 1 deferred publishing to *"three months' real use"* from 2026-08-09.
- **PNG's place once SVG lands.** Handed back by [committed-images](wayfinder/tickets/056-committed-images.md), with the cost argument spent and the trigger sharpened. `bcc render --png` no longer puts a browser into a CLI that otherwise needs only Node — decision 9 already admitted one for the SVG's height, so the marginal cost has collapsed to nothing. What never existed is the demand: PNG's stated audience is non-browser rasterizers and PDF pipelines, neither of which is a caller today, and the human case is served by the editor's own PNG export. The reason to keep declining is now a property rather than a price — a committed PNG family would carry a staleness check that **cannot run in plain Node**, which is the one thing that makes committed images safe to have at all. **The trigger is a caller that consumes canvases and is not a web engine**; when one appears, it arrives with an answer for how its images stay honest.
- **A fence with the canvas inside it.** [fence-shape](wayfinder/tickets/052-fence-shape.md) refused inline JSON on the sync argument, and the refusal has a shape: it holds while every markdown file that carries a fence sits in a repo *beside* the canvas it points at. The trigger is a fence that has no repo to point into — a chat transcript, a pasted answer, an agent writing a canvas into a document that will never be committed — where a pointer resolves to nothing and inlining is the only thing that works. Two things would come with it and neither is free: a disambiguation rule between a path and JSON, and an answer to the drift that has no dirtiness flag anywhere in this project able to catch it. Notebooks are the near-miss case that is *not* the trigger — they were ruled out on their own account.
- **Whether the fence earns a live editing surface.** Every rendering here is read-only. If a rendered fence makes people want to edit in place, that is a different product decision touching SPEC §1's "single-document editor" scope, and it opens as a fresh map, not a ticket here.

## Out of scope

- **A terse canvas DSL.** The fence's payload is settled by [fence-shape](wayfinder/tickets/052-fence-shape.md), but a hand-writable DSL is ruled out ahead of it. It is not "a second parser" — it is a **second front door** that six subsystems hang off: `parseCanvasFile` is the single funnel for file import, bundled examples, the JSON View's Apply, MCP read, MCP write and the artifact's embedded block. The refusal contract would fork (SPEC §3.3 promises JSON paths *"written the way a developer would type them"*; a DSL has line and column), migrations are defined as raw-JSON rewrites, and byte-identical round-trip backs autosave, the unexported-changes flag, the artifact embed and the examples pinning test.
- **A hand-written native-`<text>` SVG emitter.** The sheet is a 12-column grid with `subgrid`, eight flex contexts, wrapping message chips and four wrapping prose fields; reproducing that in SVG primitives means measuring text and emitting one `<tspan>` per line. SPEC §9 states one shared read-only `CanvasSheet` is the canonical visual truth so that *"editor and artifacts can never drift visually"* — a second emitter is that drift, made permanent.
- **A hosted render service** (the Kroki pattern). It costs hosting and sends canvas content into a URL, to reach a surface a committed file already covers. GitLab's Kroki integration is additionally unreachable: it is an instance-level admin setting, and the fence names it forwards come from a constant in the asciidoctor-kroki gem, so a self-hosted Kroki serving a custom `bcc` type needs a change to GitLab or the gem.
- **Markdown import.** Unchanged from [map-views](wayfinder/map-views.md): no `.bcc.md` comes back in, ever. A fence that renders is still not a fence that round-trips.
