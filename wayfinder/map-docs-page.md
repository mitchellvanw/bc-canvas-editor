# Wayfinder map: the docs page, rebuilt

## Destination

`/docs` rebuilt on two decisions: its running prose becomes committed Markdown rendered at build time, and the page ships **no client JavaScript**. The map is done when every decision behind those two is made and `SPEC.md` §2 is amended to state them — with the eight anchor ids restated as the contract that survives the move. The Markdown authoring and the pipeline code are the **hand-off**, not the destination.

## Notes

- **This map decides; it does not build.** Explicitly reversing the habit of the last four maps (hosting, examples, canonical-v5, views), each of which said "this map carries execution". Chosen at charting on 2026-08-15: Wayfinder's default is planning, and the pull to just do the work is the signal the map has ended. Task tickets are for work that *unblocks a decision*, never for delivering the page.
- **The prior research is the floor, not a decision.** `docs/research/markdown-derived-docs.md` (2026-08-15) answers the mechanism questions against primary sources and against measured probes of this repo's real build. Its §5 and §6 findings are measurements and can be relied on; its §9 recommendation is one input to [markdown-read-shape](wayfinder/tickets/069-docs-markdown-read-shape.md), not a settled answer — [furniture-boundary](wayfinder/tickets/066-docs-furniture-boundary.md) has since **corrected §9's package list twice** (`remark-gfm` missing, and fences nest a `<code>` the page's CSS is not written for) and shown that §2's furniture table **misses the largest cost of all**, Svelte's CSS scoping. Take §9 as a draft — [markdown-read-shape](wayfinder/tickets/069-docs-markdown-read-shape.md) has since **corrected it a third time** (`rehype-raw` dropped) while confirming its placement recommendation on evidence §9 did not have, and its two guard proposals are now both gone: the `<script` test is retired by construction and the built-`docs.html` test was dropped by [source-set](wayfinder/tickets/068-docs-source-set.md). Its objection 1 stands and every ticket should keep it in view: **this halves the Svelte page, it does not delete it** — and under the chosen shape, half of what stays moves from `.svelte` into a transformer rather than disappearing.
- **Settled context (from charting, 2026-08-15):**
  - **The prose moves, all eight sections at once.** Not section by section: a stalled half-migration leaves "which file do I edit?" with one more answer than it has today, which is worse than either endpoint.
  - **The section marker is droppable.** `web/src/routes/docs/+page.svelte:36–48` — the `IntersectionObserver` that bolds the sticky-nav entry under a notional reading line — is the only runtime JavaScript on the page. Trading it for a page that ships nothing is a good trade. **Now settled and dropped** — [css-section-marker](wayfinder/tickets/067-docs-css-section-marker.md) found CSS *can* reproduce both visual effects but can never set `aria-current`, so the marker is gone entirely rather than half-saved.
  - **"Section marker" is the name.** Coined at charting to retire "reading-line highlight", which collides with the **highlighter stroke** — the `linear-gradient` under each Ubiquitous Language `<dt>` (`web/src/lib/sheet/CanvasSheet.svelte:987–991`), pure CSS, on the Sheet, untouched by any of this. The section marker is website furniture and stays out of `CONTEXT.md`, which is the canvas domain's glossary.
  - **The anchor ids cannot be produced by a slugger.** The eight ids are hand-chosen short nouns, not slugs of the headings above them; run through `github-slugger` only one of eight survives (`exports`). The `sections` array (`web/src/routes/docs/+page.svelte:21–30`) already *is* the contract — id, chip, label, title in one typechecked table.
  - **No `rehype-sanitize`.** Its default schema rewrites `id="editor"` to `id="user-content-editor"`, which breaks the contract for the *homepage's* inbound links, and its own remedy for that is a client-side script this site's CSP blocks. The source is first-party and in-repo; a test that fails on `<script` in generated docs HTML is the honest defence.
  - **The narrow destination is the page.** The homepage genuinely needs its JavaScript (`goto`, clipboard, the replace dialog, the ride-to-the-finale navigation at `web/src/routes/+page.svelte:20–45`) and `/edit` is the editor. A "reading surfaces ship no JS" principle would have exactly one instance.
  - **CSP directives are global.** `web/vite.config.ts:30–44` is one set for all pages, and `style-src`'s `'unsafe-inline'` is there for the *homepage's* `style=` attributes. A script-free `/docs` gets no hash of its own, but it cannot get a tighter policy without machinery that does not exist.
- **Skills:** `/grilling` + `/domain-modeling` for the decision tickets; `/prototype` for [furniture-boundary](wayfinder/tickets/066-docs-furniture-boundary.md); `/research` for the one research ticket; `writing-copy` for any user-facing string that moves.
- **Tracker (local markdown):** tickets live in `wayfinder/tickets/*.md`. Frontmatter: `status: open|closed`, `assignee` (non-empty = claimed), `blocked-by: [ticket names]`. Frontier = open, unassigned, all blockers closed. Resolutions are appended to the ticket under `## Resolution`, then `status: closed`. Commit tracker changes to `main`.

## Decisions so far

<!-- one line per closed ticket -->

- [Research: can the section marker be expressed in CSS alone?](wayfinder/tickets/067-docs-css-section-marker.md) — **it can, and it is dropped anyway.** Named view timelines reproduce both *visual* effects at 88/88 scroll samples in Chrome 151 and 87/88 in WebKit 26.5, measured against the real built page with its JS blocked. But CSS cannot set an attribute, so `aria-current` is unreachable by construction — **a CSS marker is a two-thirds marker**, and since the two visual effects are `lg:`-gated while `aria-current` is not, it keeps the affordance for the reader with the most other recourse and removes it, at every width, from the reader with the least. WAI-ARIA's own framing (`aria-current` mirrors a visual distinction) makes dropping both together the coherent end-state. Also: the repo has **no browser-support commitment anywhere**, `timeline-scope` is unimplemented in Firefox, and caniuse has no entry for the feature. Full note: `docs/research/css-only-scroll-spy.md`.
- [Decision: the Markdown source set, and how the eight anchor ids stay a contract](wayfinder/tickets/068-docs-source-set.md) — **eight files at `docs/site/*.md`, basename as id, no frontmatter, and the shell becomes a loop.** The register (`web/src/lib/docs/sections.ts`, the `$lib/chrome/examples.ts` idiom) holds order, chip, label, title and body; the files supply bodies and never membership; the `<h2>` stays in the register because it is furniture. The session's largest finding was one the ticket had not asked for: today the id is written **twice** — literally as `<section id="editor">` *and* positionally as `sections[0]` — so `{#each sections as s (s.id)}` is what makes "the array is the contract" true rather than aspirational. The guard is three-part and mostly free: **eight named `?raw` imports** (a renamed file is a Vite resolution error, louder and earlier than any runtime throw), one test for the orphan direction, and a typed `DocsId` union the homepage's hrefs must satisfy at `npm run check`. Three more the ticket had not named: the masthead and attribution card **stay in the shell**, the four `{REPO}` links are **hardcoded** with a consistency test rather than given a placeholder word, and the one `<img>` is furniture — which sets the ceiling that **no `.md` file can carry a Vite-resolved asset**. The prose moves byte-for-byte, no `writing-copy` pass.
- [Decision: how the Markdown is read at build, under csr = false](wayfinder/tickets/069-docs-markdown-read-shape.md) — **`+page.server.ts`, `csr = false` in `+page.ts`, six packages, bodies behind `$lib/server/`.** The ticket asked for module init to be priced rather than assumed; priced against six probe routes and a real browser, it is the worst of the four, because **`csr = false` does not keep the parser out of the client build** and `data-sveltekit-preload-data="hover"` (`web/src/app.html:19`, site-wide) makes that a live cost: SvelteKit must load a page's node module to *learn* it is CSR-less, so hovering "Docs" downloads **138 KB, discards it, and full-page-navigates anyway**. The same tax is 23 KB for a prebuild and **412 bytes** for a server load. Two more that would have been inferred wrong: **`csr = false` must be declared in `+page.ts`** — from `+page.server.ts` the hover drags `__data.json` (27 KB) along — and **dropping `rehype-raw` drops raw tags while keeping their text**, so `<b>bold</b>` becomes `bold` silently, which is why the retired `<script` guard is replaced by a no-raw-HTML assertion rather than by nothing. The register splits three ways (`sections.ts` metadata client-safe, `$lib/server/docs/bodies.ts` sources + pipeline, the load returning a merged array), with `$lib/server/` chosen because it is **enforced by the build**, not by etiquette. Verified: a throwing pipeline fails `vite build`, and editing a `.md` under `npm run dev` needs no restart.
- [Decision: where the docs stylesheet lives once the prose leaves the template](wayfinder/tickets/071-docs-stylesheet-scoping.md) — **the stylesheet splits along the same seam the DOM does: 5 shell rules stay scoped, 22 body rules go global in `$lib/docs/prose.css`.** The ticket framed the home as a choice between four candidates; a measurement it had not anticipated decided it. Svelte emits the block **unlayered** and Tailwind 4 emits everything in `@layer`, so the block outranks every utility on the page — and **49 utility declarations across 18 markup sites are dead as a result**, including the attribution card's `flex justify-center` (it computes `flow-root` and has never been centred) and nine labels asking for `text-[11px]` that render at 15px. That disqualifies the Tailwind-layer home on measurement and turns the question into "which home preserves the cascade position". The split is not tidiness: `.underline-command`/`.underline-event` **exist on the homepage too, with a different implementation**, and scoping is the only thing keeping them apart — globalising the docs pair puts a second stroke under the homepage headline. Chosen: keep the block unlayered *and* delete the dead classes, before shape C copies them into the transformer. Verified: a plain `.css` imported from the route lands unlayered in its own route chunk, and **under `csr = false` Vite merges it with the scoped `<style>`, so the split costs zero extra requests**. Two of the ticket's own items dissolved — the five furniture `:global`s turn out to have no compiler reason at all (de-globalising compiles clean), and Svelte 5.56.8's `:global { }` **block** form retires the "noise on every line" objection. One thing the ticket did not name: **the attribution card moves outside `.docs`**, joining the masthead that is already there, which makes `.docs` mean exactly "the pipeline's output" — and is the only intended appearance change in the whole map (three things, on one card).
- [Prototype: where the Markdown ends and the Svelte furniture begins](wayfinder/tickets/066-docs-furniture-boundary.md) — **shape 3, the directive vocabulary**: it is the only one of the three that reproduces today's DOM (`+3` heading ids, `−1` prompt span, one removable wrapper), where one contiguous body deletes the page's visual argument and named fragments cost five source files and six shell seams per section. It also found the cost none of the three avoids — **Svelte's CSS scoping does not reach `{@html}`, so 22 of the page's 27 style rules stop matching**, and the five already `:global` are exactly the furniture ones. Corrected the research's pipeline twice (`remark-gfm` missing; fences nest a `<code>` today's `<pre>` does not) and closed a §10 open item: a repo-root Markdown glob works under `vite dev` with one `server.fs.allow` line.

## Not yet specified

- **Whether the homepage's prose follows.** `SPEC.md:35` declares the homepage prose documentary in the same breath as the docs prose, so the same argument reaches it. It cannot go script-free, but its prose could still be Markdown. **Its precondition is now met** — [furniture-boundary](wayfinder/tickets/066-docs-furniture-boundary.md) priced the seam, and the price on a mostly-furniture page reads badly: shape C's directive vocabulary only pays off where there is running prose to move, and the homepage has far less of it than the docs page. Sharp enough to state, but it is a *different page* and the destination names only `/docs`. Left here rather than ticketed; [spec-amendment](wayfinder/tickets/070-docs-spec-amendment.md) item 5 rules on whether it is in scope at all or becomes a fresh effort. **[source-set](wayfinder/tickets/068-docs-source-set.md) added evidence for the same reading from an unexpected direction:** the docs page's *own* masthead was ruled furniture and kept in the shell, because it is an `<h1>` carrying hand-placed `underline-command` / `underline-event` spans on chosen words — the homepage's marker idiom, which no directive vocabulary should have to learn. The homepage is largely made of that construction. So the argument against following is now not just "less running prose" but "its prose is load-bearingly typeset". **[stylesheet-scoping](wayfinder/tickets/071-docs-stylesheet-scoping.md) sharpened that a third time, from the CSS side:** the two pages already share the class names `underline-command` and `underline-event` while implementing them *differently* — an animated gradient on the homepage, an inset box-shadow on the docs page — and only Svelte's scoping keeps them from colliding. Whatever the homepage's prose does, it cannot join a global `.docs`-rooted stylesheet without one of the two marker idioms being renamed.
- **Whether a script-free page can carry a tighter policy than the site's.** Directives are global today and one JS-free page does not make a case. If a second and third reading surface ever go script-free, per-page directives stop being machinery-for-nothing. Watch for the trigger; do not build for it. **[markdown-read-shape](wayfinder/tickets/069-docs-markdown-read-shape.md) measured the first half of it happening on its own:** under `csr = false` the page's CSP `<meta>` already differs from every other page's — it loses its `sha256-` entirely, leaving `script-src 'self' https://static.cloudflareinsights.com`. So per-page *policies* are not the machinery-that-does-not-exist; SvelteKit already writes one per page. What does not exist is per-page *directives* in `web/vite.config.ts`. That narrows the gap but does not close it, and one page still does not make the case.

## Out of scope

- **One source feeding both `/docs` and the READMEs.** The drift the Markdown move is constantly assumed to fix, and does not. `README.md:28` leads the CLI with `npm run bcc` for someone standing in a checkout; `web/src/routes/docs/+page.svelte:298` leads with `npx` for someone who has cloned nothing. That inversion is deliberate and was recorded as a register split at `wayfinder/tickets/057-remark-plugin.md:64`. Collapsing them means flattening the register or inventing a variant mechanism, which is a DSL. Full argument: `docs/research/markdown-derived-docs.md` §3 and objection 5.
- **`bcc` fences inside the site's own docs.** Attractive — the docs would draw real canvases through the very adapter they describe — but `fencePreamble()` emits `@font-face` rules using `url(data:font/woff2;base64,…)` (`web/src/lib/fence/fence.ts:98–100`) against a `font-src 'self'` policy (`web/vite.config.ts:37`), so the sheet would draw in a fallback face. It buys authenticity on one page at the price of widening a directive for the whole site. **Most likely of the three to return** — the day something else forces `data:` into `font-src`, this is nearly free. Research: §7.5.
- **The homepage and `/edit`.** Both genuinely need their JavaScript; the narrow destination excludes them. (The homepage's *prose* is a different question and sits in Not yet specified above, not here.)
- **Writing down a browser-support matrix.** Surfaced by [css-section-marker](wayfinder/tickets/067-docs-css-section-marker.md), which went looking for one and found the repo has **none** — no browserslist, no vite target, no sentence in `SPEC.md`; Firefox is never mentioned anywhere. What exists is implied floors (`@container` and `color-mix()` already shipped in the sheet) and the WebKit-checkpoint habit. That is a real gap, but it is site-wide and this map's destination is one page — and dropping the marker removed the only reason `/docs` would have needed the answer. It returns as its own effort the day a reading surface wants a CSS feature whose support is genuinely in question.
- **Markdown as a source of truth for anything but the docs page's own prose.** `SPEC.md` is organised by decision domain and declares this copy outside itself; the wayfinder maps are argument rather than instruction. Neither is a coherent source and neither becomes one here.
